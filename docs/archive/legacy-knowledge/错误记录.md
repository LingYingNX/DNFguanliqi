## [ERR-20260702-001] 分组必须服从真实分类目录

**记录时间**：2026-07-02T09:30:00+08:00  
**优先级**：高  
**状态**：已解决  
**范围**：前端

### 摘要
从“全部补丁”打组时，组可能消失或落到错误分类。

### 错误
用户反馈：打组没反应，打组之后组直接消失。

### 上下文
历史根因是渲染层在“全部补丁”视图打组时传了空分类覆盖值，导致主进程无法按第一个选中文件的真实分类创建组。

### 建议修复
打组时不要把空字符串当成分类覆盖；应让主进程使用选中文件的真实分类，并在返回后切换到结果组所在分类。

### 元数据
- 可复现：是
- 相关文件：`src/renderer/app.js`, `src/main/main.js`

## [ERR-20260707-001] Git 并行写入索引冲突

**记录时间**：2026-07-07T00:00:00+08:00  
**优先级**：中  
**状态**：待处理  
**范围**：配置

### 摘要
并行执行同一仓库内的 Git 写操作会造成索引竞争，出现 `index.lock` 或“提交早于暂存完成”的假失败。

### 错误
```text
fatal: Unable to create '.../.git/index.lock': File exists.
Another git process seems to be running in this repository, or the lock file may be stale
```

### 上下文
在同一仓库内并行调用多个 Git 写操作时，一个命令还未完成，另一个命令就开始修改索引，导致暂存、提交和推送顺序错乱。这个问题在恢复 README、提交 `.gitignore` 和大批量 `git rm --cached` 收尾时都出现过。

### 建议修复
同一仓库内的 Git 写操作必须串行执行：先 `add`，再 `commit`，最后 `push`；不要把这些步骤放进并行工具调用里。

### 元数据
- 可复现：是
- 相关文件：`E:\BaiduSyncdisk\codex目录\DNF\.git`
- 关联条目：`ERR-20260630-003`

## [ERR-20260707-002] PowerShell 不支持直接使用 &&

**记录时间**：2026-07-07T00:00:00+08:00  
**优先级**：低  
**状态**：待处理  
**范围**：配置

### 摘要
当前 PowerShell 环境不支持 Bash 风格 `&&` 连接命令，直接拼接会触发语法错误。

### 错误
```text
The token '&&' is not a valid statement separator in this version.
```

### 上下文
为了顺序执行 `git add`、`git commit`、`git push`，尝试在 PowerShell 中直接使用 `&&` 串联命令，但当前环境的 PowerShell 版本不支持该写法。

### 建议修复
在当前 PowerShell 环境里，顺序执行多步命令时使用多次独立调用，或使用 PowerShell 自身支持的顺序写法，不要直接照搬 Bash 连接符。

### 元数据
- 可复现：是
- 相关文件：`E:\BaiduSyncdisk\codex目录\DNF`
- 关联条目：`ERR-20260630-002`
