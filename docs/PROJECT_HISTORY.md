# DNF 补丁管理器项目历史

## 项目定位

这是一个 Windows 本地桌面工具，用真实目录管理用户已有的 DNF NPK 补丁。重构目标是保留可观察功能，但以新的模块边界、类型契约和文件事务重新实现，不复制旧源码。

## 项目诞生与初代阶段

最早的归档资料（2026-07-02 至 2026-07-07）显示，项目起因是用户的 DNF NPK 文件长期散落，分类、预览、启用和停用都需要手工处理。最初产品方向已经确定为“本地文件工作台”，而不是补丁下载平台：只管理用户已有文件，操作贴近真实目录，便携运行，优先稳定和可维护性。

初代实现使用 Electron、Node.js、原生 HTML/CSS/JavaScript，界面版本为 1.1，目标是 Windows x64 portable。初代知识资料已经归档到 `docs/archive/legacy-knowledge/`；其中的旧路径、旧远端和旧源码结构只用于追溯，不覆盖当前 TypeScript/React 重构的事实。

归档没有记录最初编码的精确日期，因此“项目诞生”按两条证据保留：初代产品需求来自 2026-07 初的历史资料，当前可复现、可验证的源码基线从 2026-07-18 的 clean rewrite 开始。

## 已定案的领域决策

- 分类就是 `patch-categories` 下的真实目录。
- 组就是带 `.dnf-group.json` 的真实目录，不是虚拟标签。
- 父分类默认只显示本层项目；递归查看必须显式开启。
- 所有多文件写操作采用预检、执行、逆序补偿、原子状态提交。
- 预览图通过双击预览区域选择；右键菜单不提供选择预览入口。
- 便携版配置和回收数据位于 EXE 同级，不写旧中文目录或系统 AppData。
- 预设只保存 NPK 库内相对路径，安装只启用预设引用且不停止其它启用项；缺失引用保留并报告。
- 资源社区当前只显示“待构建”，本地维护不访问远端。
- 右侧检查器版块移除，设置入口位于侧栏左上角，原有外观设置和网格/列表功能继续保留。
- 用户壁纸、NPK、运行数据和截图不进入源码提交。
- 源码仓库和知识库是两个独立边界：知识库只保存固定五文件，不作为 Git 克隆或程序运行目录。
