# 多级右键菜单与分类移动设计

Date: 2026-07-31  
Branch: UI  
Status: approved design, implementation pending

## 目标

将补丁卡片右键菜单整理为 Windows 风格的多级菜单：一级菜单和二级菜单贴边显示，不增加额外间距；菜单不显示阴影，使用较小圆角。移动分类使用完整的根分类树，使用户在男鬼剑等嵌套目录中也能把补丁移动到其它分类。移动完成后，当前目录内容和侧栏分类数量立即刷新。

## 已确认行为

- 一级菜单与二级菜单直接相邻，使用 `left: 100%` 定位，不增加鼠标通道或额外间距。
- 右键菜单和子菜单移除 `box-shadow`，圆角使用 `6px`。
- 移动菜单展示补丁库根目录下的完整分类树，而不是只展示当前目录的直接子分类。
- 当前所在分类在移动菜单中保持禁用，其他可用分类可直接点击移动。
- 分类有子分类时，以真正的子菜单继续展开，按层级逐级进入。
- 点击外部区域或按 `Escape` 关闭整个右键菜单；进入子菜单不会关闭父菜单。
- 移动成功后刷新当前工作区快照和根分类快照；任一刷新失败都不显示成功状态。
- 不改变拖放移动、批量移动、移动对话框和文件事务语义。

## 架构

### 多级菜单组件

从 `ItemWorkspace` 中抽出可递归渲染的 `ContextMenu` 组件。组件接收带有 `label`、`icon`、`disabled`、`onClick` 和可选 `children` 的菜单项树，负责：

- 渲染菜单项及其图标、禁用状态和键盘可访问属性。
- 根据 hover/focus 打开带子项的菜单项。
- 将子菜单嵌套在对应菜单项的定位容器中，使用 `left: 100%` 贴边展开。
- 保持现有的外部 pointerdown 和 Escape 关闭行为。

`ItemWorkspace` 只负责根据当前选择构造动作数据，并把移动分类树传给组件，不再承担菜单层级的布局细节。现有业务动作回调保持不变。

### 移动分类树

`WorkspaceApp` 始终从 `workspace.navigationSnapshot` 构造移动目标。该快照代表补丁库根目录，并包含递归的 `childCategories`。移动目标保留分类的层级结构，而不是将所有分类压平成同一层。

构造目标时将当前 `workspace.categoryPath` 对应的分类标记为禁用，避免把补丁移动到当前目录。其它分类保留相对路径和子分类；点击叶子或目标分类本身调用现有 `onMoveTo`，不改变底层 IPC 请求格式。

### 刷新链路

`useWorkspace.refresh` 负责一次业务操作后的统一刷新：

1. 扫描当前工作区路径，更新卡片内容。
2. 当前路径非根目录时，再扫描根目录并更新 `navigationSnapshot`，刷新侧栏分类数量。

根目录工作区只需一次扫描，因为该扫描结果同时是当前快照和导航快照。扫描失败沿用现有错误提示，不清空成功状态或选择状态。

## 样式

- 保留现有菜单宽度、内边距、按钮间距和颜色方案，不再调整一级/二级菜单之间的间隔。
- `.item-context-menu.card` 和 `.item-context-submenu-panel.card` 使用 `border-radius: 6px`，不使用阴影。
- 子菜单使用绝对定位直接贴在父菜单项右侧；菜单项父容器负责子菜单的定位边界。
- 保留禁用项、hover、active、删除项颜色及现有图标样式。

## 错误处理

- 没有可用 IPC 客户端时沿用现有“桌面接口不可用”提示。
- 移动 IPC 失败时不刷新成功状态，保留现有错误提示和文件事务回滚语义。
- 当前分类或根分类扫描失败时，不宣称数量已更新，并显示现有扫描错误。
- 禁用目标不触发移动请求。

## 测试

- 渲染器测试验证普通菜单和组菜单动作仍按既有顺序渲染。
- 渲染器测试验证嵌套分类被保留为多级移动目标，当前分类禁用。
- Electron E2E 创建多个根分类和嵌套分类，验证男鬼剑目录下仍能打开其它分类目标。
- Electron E2E 逐步将鼠标从一级移动项移到二级菜单，验证父菜单不消失并能完成移动。
- Electron E2E 验证移动后源分类和目标分类数量立即更新，无需切换目录。
- 静态检查覆盖 TypeScript 和 Biome；不执行安装包或 portable 打包。

## 范围外

- 不改变补丁卡片布局、预览图、启用开关和拖放交互。
- 不增加剪切板、撤销或新的文件操作协议。
- 不引入第三方菜单库；复用现有 React、Lucide 和 CSS 约定。

## 自检

- 需求与样式决策一致：没有间距调整，只有阴影移除和圆角收窄。
- 移动目标来源、当前分类禁用规则和刷新链路已明确。
- 测试覆盖菜单交互、嵌套目标和数量刷新，范围完整。
