# 补丁工作区空状态居中设计

## 背景

补丁工作区的空状态区域当前使用固定 `min-height: 420px`，右侧工作区本身是滚动容器。窗口处于最小尺寸时，空状态卡片看起来接近居中；窗口放大后，新增的可视空间没有分配给空状态区域，卡片会停留在原来的流式位置，导致垂直方向偏移。

## 目标

- 空状态卡片相对于右侧补丁内容区居中，不以整个窗口或左侧导航为参照。
- 窗口从最小尺寸放大或缩小时，卡片持续保持在右侧内容区的可视中心。
- 窗口过小时保留当前最小可用高度，内容仍可通过工作区滚动查看。
- 不改变搜索、状态筛选、拖拽框选、补丁卡片、分组卡片和加载状态的行为。

## 设计

仅调整右侧工作区和空状态的布局规则，不修改 `ItemWorkspace` 的数据处理或事件逻辑。

`.patch-workspace` 改为纵向弹性容器，并保留 `min-width: 0`、滚动和现有内边距。工具栏、状态筛选栏等已有内容自然占据顶部空间；空状态区域设置为可伸展项目，使用剩余的右侧内容高度进行布局。

`.empty-state` 保留现有的纵向居中、水平居中和文本对齐规则，将固定高度改为“可伸展、但不低于当前最小高度”的规则。这样在空间充足时，卡片中心跟随右侧内容区中心；空间不足时，最小高度触发工作区滚动，不会压缩或遮挡空状态内容。

不增加运行时窗口监听、ResizeObserver、绝对定位偏移量或新的组件状态，避免把布局问题转化为 JavaScript 尺寸同步问题。

## 验证标准

- renderer 测试确认空状态仍然展示正确文案和图标。
- Electron E2E 在最小尺寸和放大尺寸下分别读取空状态区域与卡片的边界，确认卡片中心与右侧补丁内容区中心的误差在 1px 内。
- E2E 确认窗口放大后空状态不会只停留在固定 `420px` 区域的顶部位置。
- 搜索无结果、空补丁库和加载中的既有状态继续通过。
- 运行仓库 lint、TypeScript 检查、定向测试、构建和 `git diff --check`。
