# 虚拟补丁组设计

## 目标

补丁组是应用内的逻辑实体，不再是补丁库中的物理文件夹。创建、重命名和解散组不应改变组成员 NPK 的磁盘位置；组元数据与预览资产由应用状态管理。

## 已确认约束

- 一个组只包含同一分类目录下的 NPK。
- 一张 NPK 最多属于一个组。
- 旧的磁盘组应在升级后自动迁移。
- 应用继续保持便携模式：状态写入现有 `data` 目录，而非补丁库目录。

## 方案选择

在 `data/groups.json` 维护独立状态。每条组记录包含：

- 稳定 UUID。
- 组名。
- 所属分类的相对路径。
- 成员 NPK 的相对路径。
- 创建时间。

组预览由现有托管预览资产保存，绑定身份从组的相对路径改为稳定的组 UUID。这样重命名组或移动组都不会影响预览。

不采用分类排序文件承载组数据，避免将排序和领域实体混在同一个状态文件中；也不引入 SQLite，因为当前数据量和查询需求不足以证明其复杂度。

## 行为

### 创建、浏览与解散

- 创建组只写入组状态。成员 NPK 保持在所属分类目录。
- 扫描分类时读取组状态：组显示为卡片，已分组的成员不作为散卡重复显示。
- 打开组卡片时，按组 UUID 读取其成员 NPK。
- 解散组只删除该组状态和其预览绑定，成员 NPK 留在原分类并作为散卡出现。
- 组成员不存在时不作为可安装项返回；状态将在下一次组变更时清理空成员和空组。

### 移动、回收与安装

- 将同分类 NPK 拖入组，只建立成员关系，不移动文件。
- 将组成员 NPK 移到其他分类时，自动从原组移除。
- 将组卡片移到其他分类时，以单一事务移动全部成员 NPK，并更新组的所属分类与成员路径。
- 启用或停用组时，按组状态中记录的成员路径处理多个 NPK。
- 回收组时，回收其所有成员 NPK，并删除组状态和预览绑定，保留当前“回收整个组”的语义。

## 旧组迁移

首次启动时检测带 `.dnf-group.json` 标记的旧目录。对每个旧组执行下列可回滚事务：

1. 验证目录内容、父分类、组名和成员 NPK 不冲突。
2. 将成员 NPK 移回父分类目录。
3. 写入对应的虚拟组状态。
4. 将旧组预览迁移为按组 UUID 绑定的托管预览资产。
5. 仅在前述步骤全部成功后删除旧标记和空目录。

任一步失败时恢复已移动的文件、状态和预览，不删除旧目录。重复启动应能安全重试尚未完成的迁移。

## 接口与数据流

- IPC 的组引用改为 `groupId`，不再把组目录相对路径作为身份。
- 分类扫描读取 `groups.json` 并生成组卡片；组详情扫描按 UUID 返回成员补丁。
- 预览、安装、移动和回收服务通过组仓储解析成员路径，不再读取组目录或 `.dnf-group.json`。
- 渲染层导航状态保存 `groupId`，而不是模拟的目录路径。

## 验收与测试

- 创建、重命名、解散组均不创建或删除补丁库中的组目录。
- 组成员 NPK 的字节内容和相对路径在创建、重命名、解散时保持不变。
- 同一 NPK 不能加入第二个组，跨分类移动后会脱离原组。
- 组安装、停用、预览、回收和恢复保持既有用户可见语义。
- 旧磁盘组能一次性迁移；冲突或 I/O 失败会完整回滚。
- 覆盖状态仓储单测、库/安装/预览集成测试、渲染导航测试和端到端迁移流程。
