# DNF 补丁管理器从零重写设计

日期：2026-07-18

## 目标

在 `E:\codex目录\DNF` 建立一个独立、从零开始的 Windows 桌面应用。应用复刻现有 DNF 补丁管理器的用户可见能力和磁盘行为，但不复制旧源码结构、函数或实现细节。

完成标准：

- `重构` 是独立 Git 仓库，主分支为 `master`，没有继承父仓库或旧应用提交历史。
- Electron 应用能在开发环境启动，并能打包为 Windows x64 portable exe。
- 分类、补丁、组、启用记录、回收站和便携数据都遵守本文的磁盘契约。
- 知识库列出的现有功能均有实现或明确的自动化/手工验收证据。
- UI 使用 `前端` 目录提供的 Halo HTML、CSS、令牌和视觉资产重新构建，不把展示页直接嵌入为软件界面。
- 单元、集成、GUI 和 portable 打包门禁全部通过。

## 输入与非目标

行为依据只包括：

- `E:\BaiduSyncdisk\知识库\DNF插件管理器` 下的当前维护文档。
- `重构\前端` 下的 Halo 设计系统文件和截图。
- 旧软件可观察到的功能、文件布局和用户工作流。

旧源码可以用于确认功能入口和外部行为，但不能复制代码、模块拆分或算法实现。

明确不做：在线下载、社区分享、作者上传、复杂冲突分析、快照、多游戏目录、自动更新、混淆、加密和逆向保护。

## 方案选择

### 采用：Electron + 严格 TypeScript

使用 Electron、TypeScript、Vite、Vitest 和 Playwright。主进程负责真实文件系统和对话框，渲染进程负责状态展示和交互，预加载层只暴露类型化 API。

理由：现有交付目标就是 Electron portable；Node 文件 API 能直接表达 Windows 文件事务；TypeScript 能把路径、补丁、组、状态记录和 IPC 结果建模为不同类型，降低旧版数据漂移风险。

### 未采用：Tauri + Rust

优点是体积更小、边界更强；缺点是会同时更换桌面运行时、文件层和打包链，增加复刻风险，且无法直接利用现有 Electron 便携验证经验。

### 未采用：Electron + 原生 JavaScript

优点是搭建快；缺点是关键数据结构只能靠约定维持，无法在编译期阻止把分类路径、组路径、游戏路径或回收站路径混用。

## 总体架构

```text
Renderer (Halo UI)
        |
        | typed window.dnf API
        v
Preload boundary
        |
        | invoke-only IPC
        v
Main application services
  |- library scanner
  |- patch command service
  |- installation transaction service
  |- recycle-bin service
  |- preview/wallpaper service
  |- settings/state store
        |
        v
Windows filesystem + native dialogs
```

模块边界：

- `domain`：不可变领域类型、命令、结果和错误；不访问 Electron 或磁盘。
- `filesystem`：路径规则、扫描、哈希、原子写入和可回滚文件步骤。
- `application`：导入、移动、重命名、打组、删除、还原、启用和停用用例。
- `state`：设置、分类顺序、启用记录、回收站清单、壁纸和主题配置。
- `ipc`：解析渲染层输入，调用应用服务，返回可序列化结果。
- `renderer`：工作区状态、选择模型、命令入口和 Halo 组件。

生产模块保持单一职责。任何包含“并且”才能解释的模块都应继续拆分。

所有 JSON 都通过“同目录临时文件 -> 刷新 -> 原子替换”写入。读取失败不能静默当作空状态；应用要返回可见错误，并保留损坏文件供恢复。

## 领域模型

### 分类

- `patch-categories` 下的真实目录就是分类。
- 父分类默认只显示本层 NPK 和本层组，不递归混入子分类内容。
- 分类计数只统计本层 `.npk`；组单独作为一个可操作项目显示。
- 分类顺序存储在 `category-order.json`，实际目录仍是事实来源。

### 补丁

- 普通文件名以 `.npk` 结尾时才是补丁，扩展名比较不区分大小写。
- 补丁标识基于库内相对路径，不基于显示名。
- 文件大小、修改时间和内容哈希来自真实文件。
- 同目录同基名图片可作为默认预览；用户选择的预览记录在设置中或复制到稳定资源目录。

### 组

- 组是分类中的真实目录，并含有效 `.dnf-group.json`。
- 组内包含真实 NPK；启用组等价于在一个事务中启用组内全部 NPK。
- 组元数据至少包含格式版本、稳定组 ID、显示名和创建时间。
- 组重命名、移动、删除和还原必须连同目录、标记文件、预览图和全部 NPK 一起执行。
- 普通子分类不能被误判为组；仅标记文件有效的目录才是组。

### 启用记录

每个已启用补丁记录：源相对路径、源内容哈希、目标绝对路径、目标内容哈希、启用时间和所属事务 ID。

停用只删除仍与记录哈希一致的目标文件。目标已被外部修改时返回冲突，不删除文件，也不清除记录。

## 文件事务

所有多文件命令遵循四阶段：

1. 解析和规范化输入，拒绝越过库根或游戏根的路径。
2. 预检所有源、目标、重复名、目标冲突和可写性，不修改磁盘。
3. 按步骤执行并记录补偿动作；任何步骤失败时逆序回滚。
4. 文件步骤全部成功后原子提交状态 JSON；状态提交失败时回滚文件步骤。

核心不变量：

- 组批量启用不能留下未记录的部分安装。
- 删除已启用补丁前必须先安全停用；停用失败则删除整体失败。
- 已启用补丁重命名或移动后，安装记录同步迁移；必要时目标游戏文件一并重命名，不能遗留孤儿文件。
- 回收组时保存完整目录；恢复时恢复组标记、名称、预览和内容。
- 冲突错误必须列出具体文件，不能无提示覆盖。

## 功能范围

### 库管理

- 文件选择和拖放导入 `.npk`。
- 创建、重命名、删除和排序分类。
- 移动、重命名、删除、还原补丁和组。
- 多选、Ctrl 多选、Shift 连选和框选。
- 将多个同分类补丁打成真实组。
- 将补丁移动进已有组。
- 搜索、启用状态筛选、网格/列表视图和卡片尺寸调节。
- 显示文件名、大小、日期和启用状态。

### 游戏目录和启停

- 选择一个 DNF 游戏目录并持久化。
- 单个补丁启用/停用。
- 多个补丁批量启用/停用。
- 组整体启用/停用，使用全有或全无事务。
- 同名不同内容目标文件必须阻止覆盖并提示。

### 预览和外观

- 双击文件或组的预览区域选择图片。
- 不在右键菜单提供“选择预览图”。
- 五个壁纸槽位，支持导入、切换和删除。
- 壁纸支持色温、饱和度、对比度、缩放、透明度、模糊和位置。
- 两套主题、分类文字颜色和选中色调。

### 回收站

- 删除操作移动到应用自己的 `data/recycle-bin`，不直接永久删除。
- 清单记录原始路径、回收路径、项目类型、时间和所需元数据。
- 恢复前预检目标占用；冲突时不覆盖。
- 支持清空回收站的显式二次确认。

## IPC 契约

渲染层只能调用命名 API，不接触 `ipcRenderer`、Node `fs` 或任意路径读写。

API 按能力分组：

- `library.scan`, `library.importPatches`, `library.createCategory`
- `library.rename`, `library.move`, `library.createGroup`
- `library.recycle`, `library.restore`, `library.emptyRecycleBin`
- `installation.selectGameDirectory`, `installation.enable`, `installation.disable`
- `appearance.setPreview`, `appearance.importWallpaper`, `appearance.updateSettings`
- `settings.read`, `settings.update`, `categories.reorder`

每个请求在主进程使用 Zod 解析。返回值使用带 `ok` 判别字段的结果联合；错误包含稳定代码、用户消息和可选文件列表。渲染层对结果做穷尽处理。

## Halo UI

应用第一屏就是可工作的补丁管理器，不制作营销页。

布局：

- 顶部 52px 工具栏：导入、搜索、状态筛选、视图切换、卡片尺寸和设置。
- 左侧 240px 分类栏：全部补丁、真实分类树、回收站；分类可直接按住拖动排序，无需先选中。
- 中央工作区：面包屑、选择统计、网格或列表项目。
- 右侧可收起检查器：所选补丁/组详情、启停命令和预览。
- 模态层：重命名、打组、冲突列表、设置和清空回收站确认。

视觉规则：

- 复用 `前端/css/system.css` 的颜色、边框、间距和动效思想，迁移为应用自己的令牌文件。
- 使用近黑背景、三层表面、1px 边框、靛蓝主操作，并让成功/警告/错误颜色只表达状态。
- 控件使用 Lucide 图标；图标按钮提供 tooltip 和无障碍名称。
- 卡片圆角不超过 8px，稳定网格尺寸避免状态变化造成布局跳动。
- 壁纸是内容背景层，不降低文本对比度。
- 支持 1280x720 最小窗口和常用高分辨率；文本不能重叠或溢出。

## 错误处理

- 领域错误分为输入无效、路径越界、目标冲突、外部修改、磁盘失败、状态损坏和事务回滚失败。
- 可恢复错误显示非阻塞通知和详情；破坏性或批量错误显示模态详情。
- 状态损坏时进入只读恢复模式，禁止继续修改文件。
- 回滚失败必须保留事务日志并提示手工恢复路径，不能声称操作已取消。

## 测试策略

### 单元测试

- 路径边界和相对路径规范化。
- 分类、补丁、组扫描规则。
- 状态解析、迁移、原子写入和损坏处理。
- 安装记录匹配与外部修改判定。
- 选择、筛选和排序纯逻辑。

### 文件系统集成测试

每个测试使用独立临时目录和真实文件：

- 导入、移动、重命名、打组、删除和还原后的目录树。
- 组恢复包含 `.dnf-group.json`、组名、预览和 NPK。
- 已启用补丁重命名不遗留旧游戏 NPK。
- 组后续文件冲突时整体启用为零修改。
- 删除已启用补丁失败时库文件和游戏文件都保持原状。
- 状态提交失败触发文件回滚。

### GUI 验证

- Playwright 驱动真实 Electron 窗口完成导入、选择、打组、启停、删除和恢复。
- 截图验证 1280x720、1440x900 和 1920x1080。
- 验证右键菜单无预览图入口，双击预览区域能打开选择流程。
- 验证未选中分类可直接拖动排序。
- 验证弹窗、空状态、错误状态和长文件名无重叠。

### 打包门禁

- 在英文临时路径执行 portable 打包。
- 启动打包后的 exe，确认窗口非空并能扫描 EXE 同级 `patch-categories`。
- 确认配置和回收站写入 EXE 同级 `data`，不写 AppData 或历史中文目录。
- 确认版本号、界面版本和产物名一致。

## 交付顺序

1. 独立仓库、构建配置和测试基线。
2. 领域类型、路径边界和原子 JSON 存储。
3. 扫描与只读库视图。
4. 导入、移动、重命名和真实组。
5. 回收站与完整恢复。
6. 单补丁和组启停事务。
7. Halo 工作台和全部交互。
8. 壁纸、主题、预览和偏好设置。
9. GUI 回归、portable 打包和完成度审计。

每个切片先写能因缺失行为而失败的测试，再实现最小行为，然后运行相关回归。
