# 侧栏导航与本地预设设计

Date: 2026-07-22
Branch: UI设计
Status: approved design, implementation pending

## Goal

将左侧分类栏调整为参考图 1 的紧凑导航结构，并增加三个真实可点击的本地工作区入口：未分类、预设和资源社区。预设引用现有 NPK 文件，不复制文件；用户可以从选中的补丁创建预设，并通过一次操作叠加安装预设中的补丁。

## Confirmed Decisions

- 采用独立的本地预设模型，不复用真实文件组。
- 预设保存补丁的库内相对路径引用，不保存 NPK 副本。
- 预设安装采用叠加语义：只启用预设引用的补丁，不自动停用其他已启用补丁。
- 未分类表示直接位于补丁库根目录、没有归属分类文件夹的 NPK。
- 预设从当前选中的补丁创建。
- 资源社区暂不连接远端，点击后在主工作区显示“待构建”。
- 现有顶部全局工具栏、分类树、搜索、筛选、网格/列表、卡片尺寸、真实文件操作和外观设置继续保留。

## Scope

### Sidebar Layout

侧栏按参考图 1 的结构组织：

1. 顶部紧凑操作行：外观设置图标、新建图标和当前上下文可用的分类命令。
2. 系统入口：回收站、全部、未分类、预设、资源社区。
3. 分隔线。
4. 真实分类树：展开/折叠箭头、缩进、直接补丁计数、排序拖动和选中状态。

每个入口使用图标、名称和右侧计数。当前入口使用靛蓝/紫色选中表面；资源社区可点击但主区内容明确显示“待构建”。侧栏保持滚动，系统入口不会被分类树挤出视口。

### Navigation State

系统入口与文件分类使用独立的导航状态，不能把系统入口伪装成文件夹路径：

    type NavigationSelection =
      | { kind: "all" }
      | { kind: "uncategorized" }
      | { kind: "presets" }
      | { kind: "community" }
      | { kind: "category"; relativePath: string };

现有 categoryPath 继续只表示真实分类路径。回收站仍打开现有回收站工作流，不改变真实文件恢复事务。

all 使用现有补丁工作区和筛选能力；uncategorized 只把根扫描结果中的直接 NPK 暴露给工作区，不包含分类子目录；category 保留现有分类扫描和“包含子分类”开关；community 使用无卡片嵌套的主区占位状态；presets 使用预设专用列表视图。

## Preset Model

预设存放于运行时数据目录的 presets.json，使用现有原子 JSON 存储和恢复模式机制。建议结构如下：

    type PresetItemReference = {
      kind: "patch";
      relativePath: string;
    };

    type Preset = {
      id: string;
      name: string;
      items: PresetItemReference[];
      createdAt: string;
      updatedAt: string;
    };

约束：

- 名称必须非空，并在同一预设列表中唯一。
- relativePath 必须通过现有库路径边界校验，禁止绝对路径和越界路径。
- 预设只引用 kind 为 patch 的 NPK；组不是预设项，避免组目录语义与引用集合混淆。
- 创建、重命名、删除和修改项均通过原子写入；写入失败不改变旧文件。
- 读到损坏的预设文件时进入现有只读恢复模式，保留原始文件并显示恢复提示。

## User Flows

### Create From Selection

1. 用户在网格或列表中选择一个或多个 NPK。
2. 选中操作条出现“加入预设”图标按钮。
3. 点击后打开预设表单；用户输入名称并确认。
4. 服务验证选中项仍存在、均为 NPK 且路径在库内。
5. 原子保存预设并刷新预设列表，显示成功通知。

后续可在同一入口选择已有预设，把选中的 NPK 追加到该预设；重复引用去重，已有预设的名称和其他项目保持不变。

### Install Preset

1. 用户点击“预设”进入预设列表。
2. 每个预设显示名称、引用数量、缺失数量和安装按钮。
3. 点击安装后，服务重新解析引用并区分存在项与缺失项。
4. 对存在项调用现有批量启用服务；不触碰其他已启用补丁。
5. 成功项、跳过项和失败项通过现有状态通知/冲突结果展示。

安装是可重复的幂等操作：已经启用的引用不会重复写入；目标游戏目录未配置或保护校验失败时，沿用现有错误结果并不修改文件。

### Preset Maintenance

- 重命名只更新预设元数据。
- 删除只删除预设引用，不删除任何 NPK 或组目录。
- 查看预设显示引用项；缺失引用使用文字和图标说明，不能只用颜色表达。
- 只读恢复模式禁用修改和安装按钮，但允许查看可读的预设内容。

## IPC and Module Boundaries

在 shared IPC contract 中加入类型安全的预设请求/响应：

- listPresets
- createPreset
- renamePreset
- deletePreset
- addItemsToPreset
- installPreset

主进程新增预设存储/服务模块，负责 schema 校验、原子写入、库路径边界校验、缺失引用解析和批量启用编排。渲染进程只通过 typed API 读取/修改状态，不直接访问文件系统。现有批量启用服务作为唯一真实安装执行路径。

## Error Handling

- 空名称、重复名称、空选择和非 NPK 选择在表单或提交时给出明确错误。
- 引用文件被移动或删除时，预设仍保留；列表显示缺失计数，安装时跳过缺失项并报告具体路径。
- 原子写入失败时保留旧预设文件，显示错误通知。
- 预设文件损坏时沿用 recovery mode，不覆盖损坏源文件。
- 安装过程中已有批量事务失败时沿用现有回滚语义；不把部分成功误报为全部成功。

## Verification Plan

### Unit and Integration

- 预设 schema、名称唯一性、重复引用去重。
- 库内相对路径边界和越界路径拒绝。
- 原子保存、读取、重命名、删除和损坏恢复。
- 缺失引用解析和叠加安装编排。

### Renderer

- 侧栏入口顺序、选中样式、计数和分类树保留。
- 未分类只显示根目录 NPK。
- 资源社区显示“待构建”，不调用远端。
- 从选中补丁创建预设、追加引用和删除/重命名交互。
- 预设安装按钮调用 typed API，缺失引用显示可读反馈。
- 现有网格/列表、搜索、筛选、分类操作和外观设置回归。

### Electron E2E

- 运行时数据目录中创建预设，重启后仍存在。
- 选择两个真实 NPK 创建预设，安装后两个文件实际启用。
- 安装预设不会停用预设之外已启用的补丁。
- 删除预设不删除 NPK 文件。
- 移动/删除引用后安装显示缺失并保留其他补丁状态。
- 1280x720、1440x900 和 1920x1080 截图检查侧栏稳定、无右侧检查器、主区不溢出。

验收门禁：pnpm test、pnpm typecheck、pnpm lint、pnpm build、pnpm test:e2e 和启动器 --check 全部通过。

## Non-Goals

- 不实现在线资源社区、远程下载、账号或同步。
- 不复制 NPK 文件或改变现有真实组目录模型。
- 不自动停用当前已启用补丁。
- 不重构与侧栏/预设无关的安装、恢复或预览模块。
