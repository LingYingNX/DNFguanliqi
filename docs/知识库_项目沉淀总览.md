# DNF 补丁管理器知识库：项目沉淀总览

更新时间：2026-07-22

这份总览是知识库唯一的综合入口，合并项目历史、功能模块、使用方法、数据布局、维护规则、错误修复和长期迭代方向。源码、Git、依赖、运行数据和构建产物不放在知识库中。

## 1. 项目定位与诞生

DNF 补丁管理器是 Windows 本地桌面工作台，用真实目录管理用户已有的 DNF `.npk` 补丁。它不提供在线下载、社区分发、作者上传平台、游戏逻辑修改或逆向保护。

项目最初要解决的问题是：NPK 文件长期散落，分类、预览、启用、停用、移动和恢复需要手工处理。初始产品原则一直是：

- 只管理用户本地已有文件。
- 分类和组必须对应真实目录和真实文件。
- 便携运行，升级时保留用户数据。
- 先保证可预期、可撤销、可验证，再增加装饰性功能。

历史资料显示，初代版本使用 Electron、Node.js、原生 HTML/CSS/JavaScript，界面版本为 1.1，目标是 Windows x64 portable。初代资料中的旧路径、旧远端和旧源码结构只作为历史背景；当前可重新安装、构建、测试和启动的基线从 2026-07-18 clean rewrite 开始。

## 2. 从诞生到现在的迭代

- 确立本地文件工作台定位。
- 分类使用真实文件夹，父目录默认不递归混入子目录。
- 组确定为真实文件夹，不使用虚拟标签。
- 预览图入口确定为双击预览区域，右键菜单不保留同名入口。

- 修复多显示器断开后窗口跑到屏幕外的问题；启动时只在窗口不与任何当前显示器相交时将其移回主屏。

## 3. 软件功能模块

### 补丁库和分类

- 扫描 `patch-categories` 下的真实目录、NPK 和组。
- 创建、重命名、删除分类；删除前必须为空。
- 拖动同级分类排序，顺序保存到 `data/category-order.json`。
- 父分类默认只显示本层项目，打开递归选项后才查看子分类。

主要代码：`src/core/library/scanner.ts`、`category-commands.ts`、`category-order-service.ts`、`src/core/paths/library-path.ts`。

### 导入、移动、重命名和组

- 文件选择器或拖放导入 `.npk`。
- 导入前检查同路径、同内容和同名不同内容，禁止无提示覆盖。
- 单项或批量移动、重命名；批量失败会逆序补偿。
- 选择至少两个 NPK 后打组，软件创建真实组目录并写入 `.dnf-group.json`。
- 组可以整体移动、重命名、启用、停用、回收和恢复。

主要代码：`import-patches.ts`、`move-library-item(s).ts`、`library-commands.ts`、`group-marker.ts`。

### 选择、视图和系统导航

- 普通点击单选，`Ctrl` 多选，`Shift` 连选，拖动空白区域框选。
- 工作区控制行搜索名称或相对路径，并切换网格/列表视图。
- 工作区控制行切换网格/列表；卡片尺寸控制从界面移除。
- 左侧系统入口切换全部、未分类、预设和资源社区；真实分类树仍对应磁盘文件夹。
- 选中操作条提供启停、移动、打组、加入预设和回收命令。

主要代码：`src/renderer/workspace/*.ts`、`CategorySidebar.tsx`、`ItemWorkspace.tsx`。

### 本地预设

- `data/presets.json` 保存预设名称、时间和补丁相对路径引用。
- 预设 UI 显示引用数量、缺失数量和引用路径；删除预设不会删除 NPK。
- 安装沿用现有批量启用事务，缺失引用跳过，成功项继续叠加安装。
- 主要代码：`src/core/presets/*`、`src/main/ipc/preset-ipc.ts`、`src/renderer/workspace/usePresets.ts`、`PresetWorkspace.tsx`。

### 游戏目录和启停

- 选择并持久化 DNF 游戏根目录。
- 启用时复制 NPK 到游戏目录并写入安装记录和哈希。
- 停用只删除仍与安装记录哈希一致的文件。
- 目标文件被外部修改或发生同名冲突时停止，不覆盖。
- 组启用/停用等价于组内所有 NPK 的原子批次。

主要代码：`src/core/install/*`、`game-directory-ipc.ts`、`appearance-settings.ts`。

### 回收站和恢复

- 删除先移动到 `data/recycle-bin`，不直接永久删除。
- 回收清单保存原路径、回收路径、时间和类型。
- 恢复前检查原位置，冲突时不覆盖。
- 清空回收站需要显式确认，执行后不可由应用恢复。

主要代码：`src/core/recycle/*`、`RecycleBinDialog.tsx`。

### 预览图、壁纸和外观

- 双击 NPK 或组的预览区域选择图片。
- 预览图复制到受管资源目录，移动、回收和恢复时保持绑定。
- 壁纸提供五个槽位，可导入、激活和删除。
- 外观包括主题、分类文字颜色、色温、饱和度、对比度、缩放、透明度、模糊和位置。

主要代码：`src/core/assets/*`、`src/core/previews/*`、`src/core/wallpapers/*`、`src/core/appearance/*`。

### 状态和恢复

- 设置、安装、分类排序、回收、预览和壁纸状态都使用 Zod 校验。
- JSON 使用临时文件、写入、同步和原子替换；写入失败保留旧状态。
- 多步文件操作使用补偿动作和事务恢复日志。
- 状态损坏或事务未完成时进入只读恢复模式，不静默当成空状态。

主要代码：`src/core/state/*`、`src/core/filesystem/file-transaction.ts`、`src/main/ipc/recovery-mode.ts`。

## 4. 用户使用方法

### 启动和首次设置

1. 在源码工作目录双击 `启动DNF补丁管理器.bat`。
2. 首次启动等待 pnpm 依赖、Electron 运行时和 `out` 准备完成。
3. 选择分类；空库点击导入入口或将一个或多个 `.npk` 拖入工作区。

### 日常管理

1. 左侧选择全部、未分类、预设、资源社区或真实分类；需要查看子分类时打开递归查看。
2. 用空库导入入口或拖放导入 NPK。
3. 使用搜索和网格/列表视图定位项目。
4. 通过移动、重命名、分类排序和真实文件夹组整理补丁。
5. 选中项目后启用或停用；冲突和外部修改会被保护。
6. 不需要的项目先删除到回收站，确认无误后再清空。

### 预设工作流

1. 在网格或列表中选中一个或多个 NPK，点击“加入预设”。
2. 输入名称创建预设，或选择已有预设追加引用。
3. 打开侧栏“预设”查看引用和缺失项，点击“安装”叠加启用。
4. 删除预设只删除引用状态；被移动或删除的 NPK 会在安装时跳过并报告。

### 组和预览

1. 同一分类至少选中两个 NPK，点击打组并输入组名。
2. 双击 NPK 或组卡片的预览区域选择图片。
3. 在设置中管理五个壁纸槽位、主题和显示参数。

### 数据备份和升级

便携版 EXE 同级目录为：

```text
DNF补丁管理器.exe
data/
patch-categories/
```

预设保存在 `data/presets.json`，只包含名称、时间和补丁相对路径；备份和恢复时应与其它 `data` 状态一起处理。升级前关闭软件，备份 `data` 和 `patch-categories`，只替换 EXE 或程序文件，不覆盖用户数据。NPK、壁纸、截图和运行数据不复制到知识库。

## 5. 维护与迭代规则

### 修改前

1. 先读本总览、三份记录文件和对应 service、IPC contract、preload API、测试。
2. 明确真实文件树、状态 JSON、界面状态和错误行为四类成功标准。
3. 新功能先登记 `功能请求.md`；用户纠正或非显然经验登记 `学习记录.md`；命令失败登记 `错误记录.md`。
4. 文件操作必须走事务；UI 改动必须有渲染测试或真实 Electron 证据。

### Git 和知识库边界

- 本地只保留 `master`，Git 写操作按 `add`、检查、`commit` 串行执行。
- 软件源码、Git、依赖、`data`、`out`、`dist`、NPK、壁纸和截图只留在源码工作目录。
- 知识库固定只保留五个根文件，不建立 `docs`、`archive` 或 `superpowers` 子目录。
- 设计计划和旧归档继续留在源码仓库，不进入日常知识库。

## 6. 已解决问题与经验

- Electron 目录存在不等于 `electron.exe` 存在；启动器必须验证真实二进制。
- Electron 进程存在不等于用户能看到窗口；还要验证窗口可见性、响应状态和屏幕矩形。
- 分类、组、移动、回收和启停必须验证真实磁盘结果，不能只看 UI。
- Windows PowerShell 当前不支持 Bash `&&`；Git 写操作必须分开调用。
- PowerShell 中文显示乱码不等于文件乱码，要用 UTF-8 文件读取、真实 UI 和 JSON 交叉确认。
- 全量测试单项超时先独立重跑，再判断是否为业务回归。
- 知识库必须精选核心文件，不能递归复制源码仓库的所有 Markdown。

## 7. 当前验证基线与后续候选

当前切片验证：renderer 18 个测试文件、50 项通过；预设 Electron 流程 2/2 通过；生产构建、TypeScript 和 Biome 通过。完整门禁仍需在发布前重新运行。

候选功能：批量重命名辅助、更多排序方式、补丁分类清单导出、更完整的列表信息列、主题预设管理、更多键盘快捷键和更清晰的异常详情。

明确不做：在线补丁下载、社区分享、作者上传平台、复杂冲突分析、快照、多游戏目录实例、自动更新器、逆向保护、加密和混淆。
